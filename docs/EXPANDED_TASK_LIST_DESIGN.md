# 刘海展开任务列表

## 范围与参考

这是原有黑色硬件刘海的局部改进，保留像素动画、会话发现、排序、聊天与外部跳转，
不复制第三方界面、图标或源码。设置窗口继续使用独立的原生 macOS 设计。

- [Apple Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)：
  让任务名称、当前状态和操作容易扫描；长内容截断时仍保留可识别的标题。
- [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：
  用对齐、间距和层级区分主要内容与次要信息。
- [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：
  操作有清楚的名称；图标按钮提供提示与辅助功能标签。
- [Vibe Island 官网](https://vibeisland.app/)：参考统一会话入口、查看请求、计划审阅和
  跳回原会话的使用流程；不照搬其整体视觉表达。

## 设计取舍

| 原来 | 现在 | 原因 |
| --- | --- | --- |
| 标题、彩色徽标、Token 同行 | 标题与状态在上，来源／项目／Token 在下 | 减少长任务名被次要信息挤占 |
| 最近消息替代状态文字 | 当前状态始终可见，消息是独立的活动摘要 | 历史消息不能代表当前是否还在工作 |
| 所有等待都使用旋转指示 | 工作为 spinner；审批、问答、计划用静态符号和文字 | 区分“正在执行”和“等待用户” |
| 气泡和眼睛图标含义不明确 | 标题打开外部会话，“详情”在刘海内查看 | 区分两个导航目标，避免整行点击拦截动作 |
| 审批按钮阶梯出现 | 控件立即可用，按下／悬停仅改变颜色 | 高频操作不依赖装饰动画，保持点击位置稳定 |

使用现有 SwiftUI、SF Symbols、系统字体和 `ProcessingSpinner`，没有增加依赖。
标题 14 pt、活动 12 pt、状态／来源／操作 11 pt。中性分隔线组织任务，不叠加彩色卡片。
96 pt 行高、28 pt 列表标题、4 pt 上下间距在 `SessionListMetrics` 统一定义，窗口高度
与真实内容一致，达到用户设定的最大高度后滚动。

## 状态与安全边界

- `SessionRowPresentation` 只读权威 phase，不从旧消息猜测状态。
- `.waitingForInput` 只有存在 `completedAt` 才显示“已完成”，否则是“等待输入”。
- 普通工具请求显示查看／拒绝／允许，仍按 `sessionId + expectedToolUseId` 路由。
- AskUserQuestion 显示“回答问题”，ExitPlanMode 显示“审阅计划”，均只打开现有结构化
  交互页面。普通批准入口额外拒绝这两类请求，避免绕过计划内容及专用响应格式。
- 归档仍仅限 idle／waitingForInput；列表与快捷键共用原来的排序策略。
- 标题是独立 Button，操作按钮不是其子按钮；没有为这些操作设置默认回车或全局快捷键。
- 不修改 Hook、审批模式、声音、快捷键绑定或像素动画。

## 验收方法

`SessionRowPresentationTests` 覆盖所有 phase、两种语言、完成证据、旧消息优先级、
结构化请求分类、归档边界及列表尺寸。`SessionRowRenderingTests` 使用不进入 SessionStore
或 Bridge 的离线示例，以 456 pt 内容宽度（480 pt 面板减外边距）输出中英文截图附件。
截图的尺寸与不触发回调可自动断言；文字裁切和按钮布局仍需看图，不能由 PNG 存在推断。
真实已安装 App 的显示、点击和外部 Agent 完整回合另行验收，不以离线示例替代。

## 刘海内快捷设置

用户追加要求后，将 `NotchMenuView` 的快捷设置与任务列表一起统一：

| 原来 | 现在 | 原因 |
| --- | --- | --- |
| 彩色卡片、9 pt 小胶囊和渐变设置入口 | 中性分隔线、12 pt 控制标签、原生分段／菜单／开关 | 清楚表达选项、选中值与布尔开关，不自造基础控件 |
| 显示和系统设置混排 | 显示与行为／权限／系统与集成 | 常用外观项在前，审批单独解释，系统连接在后 |
| 三种审批模式只有短标签 | 显示模式对应说明，明确自动仅本次、信任离线持续、问答计划手动 | 权限选项不能只靠颜色区分，也不能隐藏实际后果 |
| Hook 操作期间仍可重复点击 | 更新时禁用本页开关、显示进度，失败给出恢复提示 | 避免同一视图连续安装／卸载，保留关闭失败时回滚 opt-in |
| 启动项只更新本地布尔值 | 读回系统状态，需系统批准或失败时显示提示 | 注册调用成功不等同用户已在系统中允许 |

保留常驻／隐藏、简略／详细、悬停及当前延迟、用量、三审批模式、登录启动、桥接、
语言、返回任务、完整设置与完全退出。中央分组独立滚动，顶部导航与底部两个操作
固定；不新增声音开关、不改用户值、不恢复未使用的历史菜单组件。
`NotchQuickControls` 是接收显式绑定与回调的展示组件，测试无需访问用户配置、
系统启动项或 Hook 安装器。控制器仍使用原有设置存储与操作入口。
