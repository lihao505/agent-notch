# 迟到工具结果与临时终止占位

## 已证问题

上一轮已把 Stop / 中断后没有结果的工具行关闭，但同一个 interrupted 状态也用于
真正的 CLI 中断。生产入口把所有终态当作不可更新，导致临时关闭后收到真实结果
仍没有内容；PostToolUse 已标为 success 的行也不能补上随后到达的原生日志详情。
完整 historyLoaded 跳过既有工具行，首次创建已完成工具则不区分错误或实际中断，
统一使用 success。只有工具结果的增量也不会清理缺失 PostToolUse 的精确跟踪项。

修复前 9 项隔离测试中 7 项失败，共 14 个断言失败；日志
`/tmp/agent-notch-tool-result-before.log`。
追加晚到 Hook 和缺失 Hook 跟踪项测试，2 项测试各失败 1 个断言；日志
`/tmp/agent-notch-tool-result-tracker-before.log`。
这些是实际 SessionStore 入口事件序列，不把系统服务日志或编译错误计作业务复现。
补充恢复入口时，完整历史已包含有效结果却不消费对应审批，仍停在原队首；
扩展同一用例到完整加载后 1 项测试有 4 个断言失败，日志
`/tmp/agent-notch-tool-result-restored-approval-before.log`。

## 修改范围

- 工具行增加仅内存使用的 isTerminalPlaceholder，表示回合边界关闭了没有结果的
  占位行。真实 tool_result 中断不带此标记；刷新工具输入时保留它。
- 复用 ToolCompletionResult.from 的既有错误、中断和结果文本投影，首次完整历史
  不再把 is_error 或已识别中断统一画成成功。
- 在 SessionStore 内共享精确工具结果合并。临时关闭可被真实成功、失败或中断
  结果修正；已经明确完成的工具只接受同状态的缺失字段补齐，不用重复结果替换
  首个非 nil 文本或结构化详情，也不让矛盾终态覆盖既有事实。
- 完整历史和增量的结果映射都会检查既有行，包括没有新工具消息的结果-only 批次。
  接受完成结果后移除对应 inProgress 项，不清空并行工具，不创建未知工具行。
- 精确晚到 PostToolUse / PostToolUseFailure 可修正边界占位，回合 phase、completedAt
  和终止边界仍只服从既有生命周期仲裁；工具完成不伪造整个回合完成。
- 历史同步不会直接合并待审批项。它们继续走已有带时间戳的 toolCompleted /
  Hook 仲裁，过旧、缺失时间戳的结果不能消费队列；并行审批保留 FIFO。
  完整初始/恢复历史也在提交同步内容后交付该事件，不等待另一次文件追加才更新审批。
  交付沿用历史代次保护，await 后不写回旧会话快照。
  后台合并直接读取 phase 内的请求上下文，不调用主线程隔离的 UI 便捷属性。

无 socket、Hook 协议、CLI 发送、审批策略、通知声音或页面样式变更。
没有新依赖、后台线程或轮询。只在已有同步时遍历已加载工具行，没有为迟到结果
另开文件扫描。既有只给完成 ID、没有错误详情时的 success 兼容语义保留。

## 回归范围

12 项新增测试：

1. Stop 后只有结果的增量修正占位，会话继续等待，完成时间不变。
2. 下一回合中旧工具收到失败结果，当前工具继续运行；完整与增量输入刷新都保留标记。
3. 完整历史补齐已由 Hook 完成的工具详情，行不重复。
4. 首次历史正确投影失败和真实中断，中断提示不作为正常结果文本。
5. 中断后的精确完成事件可补结构化结果，但不把 idle 恢复为工作态。
6. Hook 后补文本，再补结构化详情；重复与矛盾结果不替换首个事实。
7. 已识别的真实中断不被矛盾成功改写。
8. 没有时间戳的完整历史结果不消费待审批项。
9. 找不到匹配工具的完成结果不产生新行或新工作状态。
10. 晚到精确失败 Hook 修正占位，等待态和首次完成时间保持。
11. 缺失 Hook 时，日志完成只移除对应跟踪项，另一工具保持运行。
12. 完整历史及结果-only 增量分别以过旧/有效时间戳交付，旧结果保留两项审批，
    有效结果只消费对应队首，后续审批和工具展示仍原子一致。

夹具使用独立 parser 根目录、禁用持久化和实际文件监听，不连接真实 Agent socket。

## 未验收边界

只读界面清单本轮再次确认 Mac 锁屏；没有绕过锁屏、终止现有应用或覆盖安装。
真实快速 Stop / 中断、新回合、审批返回与工具卡片结果展开仍需解锁后验收。
中断文本识别沿用既有 parser 的格式规则，没有扩大为任意 CLI / 本地化格式。
这不是解决同一工具 ID 在不同 CLI 执行中违规复用的方案；来源间 ID 映射、
时钟偏差以及子任务结果文件的写入一致性还需各自证据。
工具行标记不持久化；离线恢复依赖现有历史结果和已知终止边界，不凭空恢复未知结果。
本轮未改 transcript 完成后的 reply socket 清理，不把内存审批队列已更新外推为
所有真实外部挂起请求均已关闭。
