# Codex 会话头缓存与日志文件身份

## 本轮范围

继续原始架构清单中 transcript 索引与状态来源的可靠性工作，不增加 Agent 或页面功能。
生命周期游标与聊天游标已有文件身份/轮换保护，但 session_meta 缓存只按路径复用。
同一路径被替换后，发现结果可能仍使用旧任务 ID 和工作目录，
从而把新文件的生命周期证据归给旧任务。

本轮在隔离目录中运行生产 ConversationParser，不读写用户真实会话或配置。
没有进行应用冷启动、真实 Codex 回合或 WindowServer 实机验收。

## 修复前证据

新增两项文件系统回归均失败：

1. 原子替换同路径文件，保持字节数、文件 mtime 和目录 mtime，实际 inode 已变化：
   同任务的 cwd 从 `/tmp/alpha` 改为 `/tmp/bravo`，发现结果仍返回旧 cwd。
2. 同路径内容换为新任务：发现结果仍使用旧任务 ID/cwd；
   查询旧 ID 得到新文件的 active，查询新 ID 却为 missing。

这证明的是生产解析器的文件路由缺口，不是已复现真实 Codex UI 串会话。

## 实现与成本边界

- 缓存校验设备号、inode、文件大小和修改时间，不再仅信任路径。
- 文件身份与签名不变时直接命中缓存；身份不可用时不假定安全命中。
- 同文件普通追加时只读取已知 session_meta 行长度，比较 SHA-256，
  头部未变则复用已解析字段，不重新解码整个初始 256 KiB 窗口。
- 缓存只保存头部长度、SHA-256 和必要的 ID/cwd，不长期保存可能很长的头部指令原文。
  复用项目已有 CryptoKit，没有新的第三方依赖。
- 头部改变或文件身份改变时，使用原有有界读取重新解析。
- 发现结果以实际头部 ID 为准；已知路径换成另一任务时，移除该路径对应的旧路由、
  旧生命周期游标和匹配路径的旧聊天游标，并登记新 ID。
- 按旧 ID 取路径时也验证 session_meta，不能继续读取另一任务的新日志。
- 发现循环复用已有 stat 属性；没有新增每秒历史目录全扫描或全文 transcript 重解析。

没有性能跑分，不把上述有界读取设计当作 CPU/磁盘耗时改善的实测。
原地改写且设备号、inode、mtime 与字节数全部不变的情形不在本轮验证范围。
并发写入与读取的完全原子快照、所有网络文件系统、真实任务迁移也未验收。

## 回归证据

新增 5 项测试覆盖：同路径原子替换、同路径换任务 ID、同 inode 头部改写、
普通追加与完成生命周期、已热身聊天游标后换任务且不跨会话泄漏消息。
最后一项使用独立 Codex/Claude 根目录：旧 ID 不返回新文件消息，
新 ID 只返回新会话内容；没有把合成日志当作真实 Agent 回合。

初始解析/索引针对性 9 项测试通过；最终完整 xcresult 为
273 passed、0 failed、0 skipped；88 项 Bridge、30 项 verifier 和发布闸门通过。
Release `CODE_SIGNING_ALLOWED=NO` 构建通过，仅证明编译链接，不证明签名、安装或运行态。
上一轮全屏入口修复的 GitHub CI 已确认通过。

## 安装态与完整目标

仍无手动解锁确认，本轮未退出、覆盖或安装正在运行的 Agent Notch。
不能宣称本轮已经改变用户正在看到的任务状态。
生命周期矩阵的真实 Codex 冷启动、快速连续回合、工具/子 Agent，以及 Claude
同会话双审批、审批中重启、并行混合超时、CodeBuddy 实验性验收均保持未完成结论。
全屏动态修改、快速 Space 切换、多显示器等实机检查也仍需继续。
