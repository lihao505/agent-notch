# 清空历史的批次与异步代次

## 已证问题

源码与隔离测试发现两层问题：

- Claude 形状 JSONL 在一次读取中遇到 /clear，累计 messages 已重置，
  但本次 newMessages 没有重置，清空前的行仍可能随增量批次交付。
  clearPending 还会被下一次读取清掉，即使原通知尚未被消费。
- 历史和增量回调只按 sessionId 写回。清空前的结果可以在清空后替换文本及
  元数据；同 ID 会话移除再创建时，也无法区分旧实例的结果。

另外，按原始 JSON 字符串寻找 /clear 标签会漏掉转义斜杠，并把助手引用标签
误当作命令。最近 2 秒的保留规则也会留下清空前文本，虽然原注释只想保留
尚未落盘的 Hook 工具占位行。

最初 8 项测试失败，共 15 个断言；日志 `/tmp/agent-notch-clear-generation-before.log`。
助手行夹具随后规范为原生 text 数组格式，夹具格式修正不算产品功能修复。
主体修复后，补充完整快照测试进一步复现首条用户消息元数据仍为清空前内容；
日志 `/tmp/agent-notch-clear-generation-targeted.log`。
管理器加载缓存回归进一步复现：加载本身发现源文件 /clear 并成功提交新历史，
却因仍按读取前代次比较而返回 false。强化断言后的修复前日志为
`/tmp/agent-notch-clear-generation-load-result-before.log`，1 项测试 1 个断言失败。

## 修改边界

1. 仅解码候选用户命令行，支持字符串和 text 块，正常 JSON 转义不影响识别。
   助手引用不会触发清空。一次批次跨多次清空时只返回最后边界之后的行。
   初次读取包含清空也发出通知；未消费的通知跨后续追加读取保留，消费后不重放。
2. 复用 IncrementalParseState 的有效 messages，在清空后校准首/末消息及工具名。
   保留既有明确 summary、会话用量及策略字段，不声称重置全会话统计。
   Claude 元数据路径改用现有 sessionFilePath，遵守同一注入根目录。
3. SessionState 增加内存历史代次。清空或同 ID 重新创建会话获得新代次，
   普通回合切换不变。代次不持久化，也不是 Hook 或审批协议字段。
4. 完整历史与结果映射在同一次 parser actor 调用取快照；加载、完整刷新及
   增量同步均在读取前捕获代次，写回时复核。增量元数据和子任务读取后的
   actor 恢复点也复核，旧结果不能清掉新实例的聊天或元数据。
   批量工具完成事件在每项交付前再次复核，前一项 await 期间的清空使余下旧批次失效。
5. 新实例、清空后的首次同步使用缓存中全部有效消息，即使增量游标已由其他
   读取推进，仍可恢复历史。恢复使用已解析缓存，不新增每秒强制全文解析；
   Claude 元数据既有全量刷新未在本轮做性能改造。
   只因防抖任务取消而丢弃已消费游标会丢消息，因此读后有效性以代次决定。
6. 完整刷新继续走 fileUpdated 语义，保留已有工具输入更新等行为；首加载仍
   走 historyLoaded。两者复用清空协调，只给工具占位行保留短暂落盘宽限，
   清空前的普通文本不因最近 2 秒内创建而保留。
7. ChatHistoryManager 的加载缓存和任务绑定历史代次，旧实例不能标记新实例
   已加载；缓存失效后可重试。UI publisher 可能滞后，不能据此取消更晚发起
   的加载，实际任务按 actor 查询及自身代次校验决定有效性。
   返回值和缓存使用实际提交的代次，自己检测到源文件清空也能报告加载成功；
   跨外部清空或会话重建的丢弃结果不能标记为已加载。

生产异步结果均携带 expectedGeneration。无代次结果仍作为内部同步事件/既有
隔离夹具的兼容注入方式，不是外部 socket 接受路径或新的信任凭据。
没有新依赖、窗口轮询、后台线程、权限、全局配置或审批策略改变。
未扩大到 arbitrary 文本中的所有 CLI 命令格式，也不宣称新实现已有性能基准。

## 验收范围

14 项新增回归，包括：首批/增量/多次清空、转义斜杠、助手引用、未消费通知、
清空后的元数据、旧完整/增量结果拒绝、同 ID 重建、近期文本清理、已消费游标
恢复、实际完整加载/刷新入口暂停后跨清空的结果拒绝、管理器缓存失效和
完整刷新仍更新 Hook 工具输入。

异步夹具调用真正的生产加载入口，provider 先从隔离 parser 取得结果，暂停
到测试确实观察到读取发生；期间完成清空及新历史写入，再释放旧结果。
初始加载和完整刷新各运行一次。provider 默认仍是现有 parser，没有线上等待钩子。
管理器使用注入的独立 store/parser，不操作 singleton 的真实用户历史。

本地最终完整测试：Swift 320 项通过、0 失败、0 跳过；包含本轮 14 项新增回归。
强化后的暂停加载用例也确认，被丢弃的历史结果返回 nil，而不是加载成功。
测试日志 `/tmp/agent-notch-clear-generation-tests.log`，xcresult：
`/tmp/agent-notch-native-transport-build/Logs/Test/Test-ClaudeIsland-2026.10.09_05-46-59-+0800.xcresult`。
Bridge 88 项、permission verifier 30 项及发布脚本检查通过，日志
`/tmp/agent-notch-clear-generation-gate.log`。Release 无签名构建通过，日志
`/tmp/agent-notch-clear-generation-release.log`。这不包含安装、签名公证或真实 Agent /clear 交互验收。

## 未验收边界

本轮不安装、不发送真实 Agent 输入，不将矩阵中的实际 /clear、快速回合、
重启、全屏、并行审批或 CodeBuddy 场景改为通过。Mac 的只读界面清单仍报告锁屏。
缓存及内容代次不证明 WindowServer 或动画性能。也不把一次 actor 调用的结果
集合外推为磁盘写入事务，外部写入仍由下一次增量读取吸收。
最近工具占位的短暂宽限沿用既有策略，尚无真实 /clear 与高频工具并发验收。
文件替换、不同 cwd 复用同会话 ID 和任意时钟偏差仍需独立完整证据。
