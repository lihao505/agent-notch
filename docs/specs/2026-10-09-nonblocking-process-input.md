# 主进程退出后的 stdin 写入收尾

## 复现与修改范围

本轮继续处理原始架构建议中的 ProcessExecutor 可靠性问题，不增加 Agent 支持或页面功能。
已有 stdout/stderr 并发排空，但 stdin 仍使用阻塞式 `FileHandle.write`。
终止回调等待写入结束，而超时回调只处理仍运行的主进程。
主进程退出、子进程继承 stdin 且不读取时，写入仍会等待子进程关闭管道，
导致调用无法及时返回。

新增真实进程夹具：Python 主进程 fork 后立即正常退出，子进程关闭 stdout/stderr，
仅保留继承的 stdin，4 秒后自行退出。向其发送 4 MiB 输入，设置 3 秒超时。
修复前输入执行约 4.09 秒才结束，`< 2 秒` 的断言失败，证明存在上述缺口。
夹具不访问用户文件，不使用 Agent Notch 的生产 socket 或真实 Agent 会话。

## 实现

- stdin 使用 `O_NONBLOCK`，保留原描述符 flags 与 `F_SETNOSIGPIPE` 信号保护。
- 每次最多写入 64 KiB，正确累计部分写入，并重试 `EINTR`。
- 管道满时以最多 50 ms 的 `poll` 等待，然后重新检查取消、超时和主进程存活状态。
- 主进程已退出且仍有输入未送达时，记录普通 `standardInputFailed`，关闭本次写入端。
- 保留既有结果优先级：取消、超时、子进程真实非零退出及 stderr、输入失败、成功。
- 不修改全局超时策略、同步执行 API、进程树身份算法或子进程杀进程策略。
  自然退出场景不会为了清理输入而追杀已脱离主进程的后台任务。
- 不记录提示词或输入内容；没有新第三方依赖。

## 本地回归证据

ProcessExecutor 原有 4 项测试继续通过，新增 5 项：

1. 主进程退出、子进程仍保留 stdin：修复后整条用例约 0.096 秒，返回输入失败，
   不再等待夹具子进程的 4 秒存活期。
2. 大型含中文输入跨多次部分写入：子进程结果与进程内 CryptoKit 计算的 SHA-256 一致。
3. 主进程不读取 stdin：0.2 秒预算产生 `timedOut`，及时结束。
4. 子进程输出 READY 后主动取消：返回 `cancelled`，及时结束。
5. 子进程拒绝配置并退出：保留 exit 7 与 `configuration rejected`，不被输入错误覆盖。

针对性 9 项测试通过；完整 xcresult 为 261 passed、0 failed、0 skipped。
发布闸门通过，包含 88 项 Bridge 和 30 项 verifier 测试。
Release `CODE_SIGNING_ALLOWED=NO` 构建通过，仅证明编译与链接，不证明签名、安装或运行态。
