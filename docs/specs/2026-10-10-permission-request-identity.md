# 审批连接身份与迟到回调

## 问题与边界

此前 Socket 的字典以完整 sessionId / toolUseId 路由，但超时回调和本地响应
完成回调仍只携带这两个字段和时间。旧回调在队列或 actor 调度中迟到时，
可以消费同 ID 的替代请求；同 ID、同源时间或缺少源时间时，时间戳不能代替
连接身份。响应发送前也需要复核，否则旧按钮可能把决定发给替代连接。

本轮不修改 Bridge 协议、审批策略、超时预算、全局配置或 UI 视觉样式。
不以连接级夹具替代真实 CLI、应用重启、全屏、动画或多显示器验收。

## 实现

- 原生服务为每条实际待回复连接生成 UUID，附在进程内 HookEvent；CodingKeys
  明确不含该字段，客户端不能通过 JSON 指定身份，回复也不增加外部字段。
- PermissionContext 及队列保留 UUID。同键替代请求保留 FIFO 位置，但更新
  登记时间、身份和输入；不继承被替代请求的输入。同一次请求的元数据刷新
  才保留原始时间和补充已有输入。
- Socket 响应 API 必须传非空 expectedRequestID。服务在自己的串行队列及
  字典锁下复核当前请求，再移除、编码和写回；不匹配则不消费连接。
- 审批、自动审批、拒绝、问题回答、计划批准均携带渲染时的身份，Monitor
  读取当前 Store 后再次检查。普通审批/拒绝按钮通过 bindRequestAction
  同时捕获工具 ID 和 UUID，而非依赖动画期间变化的 UI 状态。
- 成功、拒绝、发送失败、过期回调带原请求身份；Store 在生命周期时间戳
  仲裁前检查对应队列项。nil 只匹配内部未标记上下文，不是绕过原生身份校验。
- 超时定时器也比较 UUID，不再用收到时间充当唯一连接身份；回调的 resolvedAt
  在实际过期时捕获，而非等待 Monitor 消费时重新生成。

既有生命周期仲裁、精确工具完成与批量终止边界保持。该身份是应用进程内的
连接身份，不是持久化会话代次，也不能识别没有携带身份的旧外部工具结果。

## 回归范围

新增 9 项 Swift 用例：

1. 同键替代保留 FIFO、更新身份/时间，不继承旧输入；同身份元数据刷新仍可补齐。
2. 批准、拒绝、失败、未标记回调，在替代、clear、同 ID 会话重建后均不能消费新请求。
3. 带正确身份的三种回调仍能处理非队首项，不消费当前队首。
4. 身份不编码到 wire，伪造 JSON 字段不能设置原生身份。
5. 私有连接同键替代，源时间相同及缺失两种情况：旧决定被拒绝，新连接真实收到 deny。
6. 旧决定已送达或旧客户端断开导致真实发送失败后，延迟 Store 回调不能消费替代项；
   新客户端实际收到响应并可正常消除自己的队列项。
7. 原始连接按真实 1 + 2 秒预算过期到 EOF；回调可处理原项，但延迟交付不能消费替代项。
8. 替代后旧定时器到期，不关闭新连接、不报告新请求失败，新客户端仍收到响应。
9. 同工具 ID、同时间的卡片替换后，旧批准/自动批准/拒绝绑定仍捕获旧 UUID。

连接级测试使用 UUID 私有 AF_UNIX 路径与禁用持久化、文件同步及全局副作用的
独立 Store，不接入生产 socket。测试回调收集器以锁保护数据，显式延迟交付
Store；不是生产回调已经迟到的实机观察。
